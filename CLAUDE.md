# Workout tracker — working rules

Personal workout app for Ar (one user, no login — that is a deliberate
decision, not an omission). Next.js 14 + Prisma/Neon, deployed on Vercel,
wrapped in a Capacitor iOS shell that points at the live site
(`capacitor.config.ts` → `server.url`), so **a push to `main` is a deploy
to the phone he trains with** — usually within a minute, no Xcode.

Two sessions work this repo: a **cloud session** (program logic, data,
schema, CI) and a **Mac session** (UI in the simulator, `ios/`, `native/`).
See `docs/WORKFLOW.md`. Coordinate through `main`; pull before editing.

## Rules that were learned the hard way

Each of these broke something real. Do not relearn them.

1. **Never put `prisma db push` in the build script.** It runs on every
   deploy against the live database and took production down twice
   (`e4fa396`, `7840432`). Schema changes go through the **Apply schema**
   GitHub Action, which previews a `migrate diff` first. The build script
   in `package.json` carries a warning comment — leave it there.

2. **Weights are not comparable across gyms.** Same exercise, different
   machine, different stack. Anything derived from a weight — last-session
   prefill, personal records, learned pin increments — must be scoped by
   gym (`gymScope` in `src/app/actions.ts`). Untagged history is B_Fit.
   The first unscoped aggregate shipped a would-be fake PR bug.

3. **Check UI on the device/simulator, not the browser.** The iOS
   date-field paint-over, the sticky header hiding behind the Dynamic
   Island, and the draft pill clipping three screens were all invisible in
   a browser. If a change touches layout, someone has to look at it in the
   simulator before merge.

4. **Weight stacks move in pins, not kilograms.** A jump from 23→27.5 kg
   is one pin, not a user error. Progression logic learns per-machine pin
   spacing (`learnPinIncrements`); do not assume 2.5 kg steps.

5. **Commit messages are not implementation.** A commit once described a
   CI workflow in detail that was never actually committed; nothing was
   testing PRs for weeks. Verify the file exists, not the message.

6. **HealthKit reads freeze at permission-request time.** All 21 types
   (17 original + blood-pressure halves, irregular-rhythm category and
   AFib-burden, added Aug 2026) are
   requested up front in the Swift bridge. Adding a read type later means
   the user must reinstall/re-grant. `native/HealthKitBridge/` is the
   source of truth; the `ios/App/App/` copy is generated by
   `npm run ios:deploy`.

## The coach layer is deliberately dormant

Waves 3–4 built an AI coach (brief, chat, coach-written gap
notifications). The owner chose to run **without** `ANTHROPIC_API_KEY` —
$0, and the app is byte-for-byte the deterministic app. This is a
decision, not a setup gap: do not nag about the key. `docs/COACH.md`
has the two-minute setup if he ever changes his mind.

## Design system (Aurora)

- Glance rule: **≤2 short lines + numbers per card**; sentences go behind
  a `<details>`/ⓘ tap. "Say each thing once" — the derived layer
  (HomeVerdict) speaks; raw data does not repeat it.
- Day A = violet, Day B = teal, ember is reserved for the return-protocol
  ramp. RPE 1–4 = Easy/Med/Hard/Grind (`rpe-easy/med/hard/grind` tokens).
- Cards (`.card`, `.card-lg`), accents `acc-teal/violet/ember/cyan`. The
  current LOOK is **Chroma** (owner-picked Aug 2026: bone ground, ink
  lines, offset solid shadows) — 'Aurora' survives only as the family
  name in docs and code identifiers.
- **Two skins, one boundary (owner, 2026-08-30): the training routes
  (`/train`, `/program`, `/stats`, `/workouts/*`, `/progress/*`,
  `/exercises`) wear Volt** — the July design canvas's Direction B: OLED
  black, `#CDFF00`, mono kickers — via `[data-domain='volt']` on `<html>`
  (pre-paint script in `layout.tsx` + `DomainTheme.tsx`; the two regexes
  must stay identical). Health routes and Home stay Chroma. The owner
  REJECTED the token-swap-only hybrid ("really bad design", 2026-08-30):
  training screens carry Volt STRUCTURE — masthead (volt-topline /
  volt-h1 / volt-tape), section labels auto-render as skewed volt
  kickers, the queued day is a solid-volt directive card (volt-card-
  primary + volt-letter + volt-startbar), protocol frames use
  volt-protocol corner brackets. New training screens must speak this
  language, not dark-Chroma. Day colors
  and RPE meanings survive on both grounds. The volt CSS block overrides
  literal-hex utilities per actual usage — it was GENERATED by grepping
  the source; when adding a new `acc-*`/`rpe-*` opacity step to a
  training screen, add its volt override too (an unlisted step renders
  dark-on-black). `@apply` inlines declarations, so component classes
  like `.card` need direct overrides — overriding the utility alone
  does nothing (this bit once).

- **White text on the deep fills (owner, 2026-08-30).** The teal/violet
  action buttons keep `text-white`, on both grounds. A contrast pass
  once switched them to ink (2.49:1 vs 8.4:1) and the owner reverted
  it — his eyes, his call. Do not re-ink them for WCAG.

## The health domain (Wave 5)

The app is **AR Health** (the owner's name, 2026-08-26 — 'Aurora' is only
the design system): training AND a personal Mounjaro/health
tracker (injections, GI, AF, CPAP, BP, labs — docs/HEALTH.md has the
laws). Tracker, not diagnostic: correlation language only, "not enough
data yet" over thin charts, nothing ever suggests a dose. The treatment
clock anchors at the first LOGGED injection; checkpoint weeks prescribe
nothing. Weight stays ONE store (BodyStat) shared by both domains.

## The program, in one paragraph

Two alternating machine days (A: legs/push+core, B: back/pull+posterior),
scheduled dynamically from behaviour: train → recover next day → the other
day is queued (`getDynamicPlan`). A layoff of `BREAK_THRESHOLD_DAYS` (21+)
days triggers a 4-week return ramp (REBOOT 60% → RESTORE 100%) that
pre-scales weights and caps RPE; repeat breaks rejoin at week
`REJOIN_AT_WEEK`. Two gyms: `bfit` (B_Fit — Life Fitness/Hoist/Hammer,
default) and `work` (Alrajhi Tower — Precor + one Hoist crossover that
substitutes for the five machines that building lacks; see
`src/lib/gym-equipment.ts`). All stacks at both gyms are read in **kg**.

## Commands

- `npm test` — prisma generate, tsc, then `scripts/coach-tests.ts`
  (assertions against the real exported history in `data/`).
- `npm run build` — build as Vercel runs it. Works with an unreachable
  `DATABASE_URL`; the sandbox has no database access.
- CI (`.github/workflows/tests.yml`) runs typecheck, lint, assertions and
  the build on every push and PR.

## Review roles

`.claude/agents/` defines the review team: trainer, device-tester, editor,
adversary, data-steward. Run the relevant one before merging work in its
area — each exists because its blind spot already bit us once.
